# Sparse Graph Backend — Architecture & Status

Living document. Last updated: 2026-08-21 (Commit 9: distance family - sparse-backend migration complete).

## Why

`nwcommands`' `NWdef` Mata class stored every network as a dense `real matrix edge` (N×N), regardless of actual density. Creating a network allocated O(N²) memory unconditionally (`J(nodes,nodes,0)` in both `nwfromedge.ado`'s `make_matrix()` and `NWdef::init_edge()`), making the package impractical above a few thousand nodes. Full technical audit and design in the original architecture report (superseded by this document as the living status reference).

## What exists now (Commits 1-9, complete)

All in `unw_core.do` on the `NWdef` class, unless noted.

- **Sparse index fields**: `rowptr`/`colidx`/`cweight` (CSR out-neighbors), `rowptr_in`/`colidx_in`/`edgeid_in` (CSC-style in-neighbors, directed networks only — undirected ties are already stored symmetrically in the forward index, so `neighbors_in()` falls back to `neighbors()`). `edgeid_in` points back into `colidx`/`cweight` rather than duplicating weights.
- **Accessors**: `neighbors(i)`, `neighbors_in(i)`, `degree(i)`, `degree_in(i)`, `has_edge(i,j)`, `edge_weight(i,j)`, `edgelist()` — O(1) or O(degree) each, built lazily via `ensure_sparse_built()`/`build_sparse_index()` from whichever representation (dense or sparse) is authoritative, and invalidated by every mutating method (`sparse_built = False`) plus a public `invalidate_sparse()` for the one external raw-pointer-write caller (`nwreplace.ado`).
- **Genuinely sparse-native construction**: `create_by_name_sparse()` + `init_edge_sparse()` (establish node identity without dense allocation) + `set_edge_from_triplets(ego, alter, weight, directed)` (builds the CSR/CSC index directly from an edge list — O(nnz log nnz), never touches `edge`).
- **Lazy dense materialization**: `edge_dense_built` (BOOL field — missing/True means `edge` is already valid, the default/unaffected legacy path; explicit False means "build on demand"). `ensure_dense_built()` is called at the top of all five `get_matrix*()` accessors and materializes `edge` from the sparse triplets on first real demand, **guarded by `nw_max_dense_nodes`** (`unw_defs.ado`, currently 20,000) with an informative error (`errDenseTooLarge`, code 484) instead of a silent multi-gigabyte allocation attempt above that size. `check_valued()` was also made sparse-aware (reads `cweight` directly) to avoid forcing materialization just to answer "is this network valued."
- **Migrated algorithms**: `calculate_components()` (BFS via `neighbors()`/`neighbors_in()`, byte-identical output to the prior dense implementation, verified), `calculate_clustering()` (all 5 modes; also fixed a genuine pre-existing self-inclusion bug, see below), `calculate_betweenness()` (Brandes' algorithm; also fixed a genuine pre-existing total non-functionality, see below), `get_outdegree()`/`get_indegree()`, `nwneighbor.ado` (uses `neighbors()`/`neighbors_in()` directly, not the dense matrix).
- **`nwfromedge.ado` rewired to sparse-native construction** (Commit 8): its old `make_matrix()` Mata function (a plain `J(nodes,nodes,0)` dense allocation, filled cell-by-cell from the same triplets already available in Mata) is gone. The command now builds directly via `create_by_name_sparse()` + `set_edge_from_triplets()`, mirroring the direct-construction pattern already used by `nw2project.ado`/`nwattime.ado` — this closes the single largest remaining O(N²) allocation on the package's ordinary, most-common usage path (turning a plain edgelist into a network). `nwset`'s own `edgelist` option is a thin wrapper dispatching straight to `nwfromedge`, so it inherits this for free.
- **Distance family migrated to sparse-native algorithms** (Commit 9, the migration's last remaining item): `calculate_distances()`'s two branches now dispatch to `calculate_distances_bfs()` (unweighted all-pairs, forward BFS via `neighbors()`, O(n·(V+E)) — replaces `Brute_dist()`'s O(n) matrix-power iterations, each O(n³), so O(n⁴) worst case) and `calculate_distances_dijkstra(alpha)` (weighted all-pairs, same linear-scan-extract-min structure already established for `calculate_betweenness_weighted()` — Mata has no built-in priority queue/decrease-key — but with a `neighbors()`/`edge_weight()`-based adjacency/cost cache instead of rescanning a dense row per relaxation; replaces `Dijkstra_dist()`). `calculate_distance_pair()` is a single early-exit BFS seeded from the source's own out-neighbors (O(V+E) with early exit, replacing the old O(n⁴)-worst-case matrix-power loop) — deliberately *not* pre-marking the source visited at distance 0, since the prior implementation's `calculate_distance_pair(i,i)` returns the length of the shortest **cycle** back to `i` (not trivially `0`) whenever no direct self-loop edge exists, confirmed via direct probe before migrating and reproduced exactly. `calculate_distances_without()` iterates `edgelist()` (O(nnz), one row per stored sparse entry) and calls a new `bfs_dist_excluding(source, target)` helper per edge — O(m·(V+E)) instead of the old O(m·n³) (m = edge count), and never mutates `edge` through the `get_matrix()` pointer the way the old dense implementation did (it zeroed `edge[i,j]`/`edge[j,i]`, recomputed, then restored the two cells). All four migrated functions were verified byte-identical against the prior dense implementation across undirected/directed/valued/unvalued/disconnected/self-loop/asymmetric-reverse-arc cases (see `cscripts/test_sparse_distances.do`) before the old `Brute_dist()`/`Dijkstra_dist()`/`Dijkstra()` standalone functions' own dense call sites were rewired — those three functions themselves are left unchanged (still used by `nclan_diameter_ok()` on small induced subgraphs, an unrelated, already-bounded use that doesn't need sparse treatment).
- **Scalability**: `lib/benchmark_sparse.do` gained a distance-family section. The unweighted family (`calculate_distances_bfs()`/`calculate_distances_without()`/`calculate_distance_pair()`) is benchmarked at 5,000 nodes/25,000 edges (O(n·(V+E)) scaling, `edge_dense_built` confirmed 0 throughout). The weighted family (`calculate_distances_dijkstra()`) is benchmarked separately at a smaller 300-node/1,500-edge tier, since its extract-min step is still O(n³) regardless of sparsity (the same accepted Mata-has-no-heap tradeoff `calculate_betweenness_weighted()` already lives with) — its real win is that edge relaxation is O(degree) via `neighbors()`/`edge_weight()` rather than an O(n) dense row scan, and the dense matrix is never built.
- **Proven at scale**: `lib/benchmark_sparse.do` builds and queries networks at 1k/10k/100k nodes (10k/100k/1M edges). At the 100k/1M tier: 1s to build, near-instant degree/neighbor queries, 7s for full connected-components analysis, `edge_dense_built` confirmed `0` throughout (the dense matrix — which would require ~74.5GB — was never constructed). Run: `/Applications/Stata/StataBE.app/Contents/MacOS/StataBE -e do "lib/benchmark_sparse.do"`.

## Bugs found and fixed along the way (all pre-existing, none caused by the migration itself)

- `calculate_clustering()` had a self-inclusion bug (dead code — zero `.ado` callers — from `select()` treating a missing mask value, present whenever self-loops are disabled, as "keep"). Fixed explicitly.
- `calculate_betweenness()`/`nwbetween` had **never once run to completion** in this codebase's history: a call to `dequeue()`, which was never defined anywhere, plus a stray syntax-breaking brace in `nwbetween.ado`. Both fixed; `dequeue()` added as a standalone Mata utility (pop-front on a row vector, verified Mata passes matrix arguments by reference).
- Once `nwbetween` could run, two more bugs surfaced: undirected betweenness was exactly double the standard value (classic unhalved Brandes double-counting — fixed with an explicit `if (!isdirect) Cb = Cb :/ 2`), and the `nosym` option silently did nothing (checked an unpopulated local `` `sym' `` instead of `` `nosym' ``) — fixing that exposed a third bug (the post-symmetrize cleanup path referenced a clobbered `netname` local instead of the already-saved `oldnetname`).
- `build_sparse_index()`'s reverse-index scratch array (`rowidx`) was originally allocated with `n` (node count) rows instead of `nnz` (edge count) rows — silently wrong/erroring on any directed network with average degree > 1. Found via full-suite regression testing (a dense 20-node/380-edge directed network), fixed, and covered by a dedicated permanent regression test.
- **Found while rewiring `nwfromedge.ado` (Commit 8), all fixed**:
  - A fresh Stata session's global `nw` (the single `NWs` Mata variable anchoring all network state) is never initialized until something calls `nws_create()`. `nwset.ado` already guards this for itself; `nwfromedge.ado` — which, unlike `nw2project.ado`/`nwattime.ado`, can legitimately be the very first network-creating call in a session — did not, and hit `type mismatch: transmorphic found where struct expected` on `.add()`. Fixed with the same guard `nwset.ado` already uses.
  - `get_nodenames_from_string()` returns a column vector; `create_by_name_sparse()` requires a row vector. `nwset.ado`'s own call site already transposes it; the new call site initially didn't.
  - `nw_syntax`'s c_local exports (`directed`, `labs`, etc.) silently clobbered `nwfromedge.ado`'s own identically-named option-parsing locals, since both share the same program scope — `nwfromedge`'s auto-symmetrize-detection block always saw the network's own post-construction `directed` state instead of the user's option. Fixed with `nw_syntax`'s own `other()` namespacing option (`other(other)` → `` `othernetobj' `` etc.), the same convention `nwrecode.ado` already uses for exactly this reason.
  - `check_symmetry()`/`symmetrize()` read/wrote the dense `edge` field directly without calling `ensure_dense_built()` first, unlike every `get_matrix*()` accessor — harmless when every network was always constructed dense-first, but silently wrong (operating on an empty/stale `edge`) once a network could be built sparse-natively and never touch `edge` at all. Fixed by adding `ensure_dense_built()` to both, matching the rest of the class's own convention.
  - `isselfloop` has no `zap()`-time default (a fresh `NWdef` leaves it at Mata's missing-scalar default, not `0`), so `ensure_dense_built()`'s own diagonal-exclusion (`if (isselfloop == 0) _diag(e,.)`) never fired unless something called `set_selfloop()` explicitly. `nwset.ado`'s dense `mat()`/varlist path always does this (defaulting to `false` when its own `selfloop` option isn't passed); the new direct-construction call site didn't, silently including the diagonal in `get_density()` and other diagonal-excluding stats. Fixed by calling `set_selfloop(0)` explicitly, matching `nwset.ado`'s own default.
  - `set_edge_from_triplets()` stored every `(ego, alter, weight)` triplet verbatim, including `weight == 0` rows. Every dense `edge` matrix treats `0` as "no tie" for free (an unset `J(n,n,0)` cell already reads as `0`); a sparse index has no such implicit background value, so an explicit zero-weight triplet silently became a *real* stored tie instead of being absent — found via `nwcomponents`' own regression test (a value-0 edgelist row was keeping an otherwise-isolated node connected). Fixed by filtering `weight != 0` triplets before building the sparse index, in `set_edge_from_triplets()` itself (so `nw2project.ado`/`nwattime.ado`, which call it directly, get the fix too).
  - `nwsym.ado`'s own `r(is_symmetric)` was documented (its own help text) as the string `"true"`/`"false"` but actually stored via `st_numscalar` as `0`/`1` — a pre-existing bug, not caused by this migration, but only surfaced now because fixing it to match its own contract (needed for `nwfromedge.ado`'s auto-symmetrize check, which already correctly compared against the string form and was therefore always silently broken) broke two *other* callers (`nwgenerate.ado`, `nwimport.ado`) that had come to depend on the buggy numeric form. All three now agree on the documented string convention; `nwimport.ado` also had an adjacent unrelated quote typo (`` "`d" `` for `` "`d'" `` ``) fixed in the same edit.
- **Found while migrating the distance family (Commit 9), fixed**: an early draft of `bfs_dist_excluding()` seeded its BFS from `source`'s own neighbors without pre-marking `source` itself visited (needed to correctly handle the self-loop case, `calculate_distances_without()` calling it with `source==target`) — but this silently broke the ordinary, non-self-loop case on any undirected network: removing edge `(i,j)` doesn't remove `i` from node `j`'s own (symmetric) neighbor list, so a path could "reach `i` again" through the very edge that was supposed to be excluded, once it looped back through an intermediate node. Caught immediately by re-running the exact probes that had already verified the function (a simple undirected path graph, where every edge removal must disconnect), not assumed still correct after a "safe-looking" follow-up change. Fixed by branching: pre-mark `source` visited (blocking any path back to it) in the ordinary `source != target` case, and only skip that pre-mark for the genuine `source == target` self-loop case — verified against the actual prior dense implementation on a hand-built self-loop network (extracted from git history and run directly, not just reasoned about) before and after, byte-identical both times.

## Testing

`cscripts/test_sparse_index.do` (dual-mode BFS-vs-`calculate_components()` proof, self-loop/empty/complete-graph/non-numeric-node-ID coverage, the directed-density regression case for the `rowidx` bug) and `cscripts/test_sparse_lazy_dense.do` (triplet construction, zero-edge networks, the 25,000-node size-guard case) are the permanent regression tests for the earlier sparse-index work. `cscripts/test_nwfromedge.do` gained two new cases for Commit 8 (auto-symmetrize detection on a reciprocal edgelist without the `undirected` option; a zero-weight triplet correctly leaving its node isolated); `cscripts/test_nwsym.do` gained a direct `nwsym, check` test asserting `r(is_symmetric)` is the string `"true"`/`"false"` for both outcomes. `cscripts/test_sparse_distances.do` (new, Commit 9) covers all four migrated distance functions against dense-captured expected values: undirected/directed/valued/unvalued, disconnected components and isolates, the self-cycle `calculate_distance_pair(i,i)` case, the asymmetric-reverse-arc case for `calculate_distances_without()`, a genuine self-loop edge, and `alpha` variations (0/1) confirming the "dijkstra" alg path collapses to plain hop-count at `alpha=0`; `nwgeodesic`'s own pre-existing test (already covering `alpha` 0/0.5/1/1.5, symmetrization, eccentricity/radius/diameter) and `nwbridges`'/`nwpath`'s own pre-existing tests all re-verified passing unchanged. All pass in dev mode (`do unw_core.do`) and production mode (against the compiled `lib/lnwcommands.mlib`, via the matching copies in `lib/cscripts_prod/`). Full-suite regression sweep as of this document (110 files, both modes): clean except pre-existing dead-external-URL issues (`nwdegree`/`nwexport`/`nwplot`/`nwplotmatrix`/`nwshared`/`nwsimmelian`/`nwuse`/`nwvalue` all `r(601)`; `nwimport` `r(6750)`) and two untracked, unrelated in-progress files (`test_nwaddnodes.do`/`test_nwcollapse.do`, paired with uncommitted, unfinished rewrites of `nwaddnodes.ado`/`nwcollapse.ado` from earlier work — not part of this unit, left untouched) — none caused by or related to this migration.

## Status: migration complete

All nine commits are done. Every command-facing code path (`nwfromedge`/`nwset`'s `edgelist` option, `nwgeodesic`/`nwcloseness`/`nwreach`/`nwbridges`/`nwpath`, `calculate_components`/`calculate_clustering`/`calculate_betweenness`, `nwneighbor`) now goes through sparse-native construction and/or sparse accessors, with lazy, size-guarded dense materialization as the compatibility fallback for anything not yet migrated. The two standalone functions still fully dense (`Brute_dist()`, used only by `nclan_diameter_ok()`'s small induced-subgraph work; the eigendecomposition inside `nwevcent`) are dense by necessity or deliberately out of scope, not oversight — see `docs/ROADMAP.md` for the reasoning on each.

## Rebuilding

`lib/build.do` recompiles `lib/lnwcommands.mlib` from `unw_core.do` (`do unw_core.do` → `mata mlib create` → `mata mlib add lnwcommands *()` → `mata mlib index`) — required after any `unw_core.do` change before production-mode testing.
