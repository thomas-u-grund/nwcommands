\chapter{Missing data, structural zeros, and what is not implemented}\label{ch:missing}

The first part of this chapter explains how \nwsaom{} treats data that are unknown (missing ties and behavior values) or fixed by design (structural zeros and ones). The second part is an honest list of what RSiena offers and \nwsaom{} does not.

\section{Missing data: \opt{missnet()} and \opt{missbeh()}}\label{sec:missing}
Missing data here means dyads or actors whose true value at a wave is \emph{unknown}. This is RSiena's regular missing-data mechanism and it is different from composition change (actors who are not part of the network at a wave, \opt{present()} or \opt{joinat()}/\opt{leaveat()}): a missing tie is uncertainty about an otherwise active actor. The two can be used together.

\paragraph{Specifying missingness.}
\begin{itemize}
\item \opt{missnet(matlist)} takes one 0/1 $n\times n$ \emph{matrix} name per wave, in the order of \opt{wave1()}/\opt{wave2()} or \opt{waves()}; a 1 marks a dyad missing at that wave. It is a raw Stata matrix, not an \texttt{nwset} network. Build it with \texttt{matrix input} or \texttt{mkmat} from your own indicator. With two waves, \texttt{missnet(m1 m2)}.
\item \opt{missbeh(varlist)} takes one 0/1 \emph{variable} per wave (the same one-variable-per-wave convention as \opt{present()}), marking the actors whose behavior value is missing at that wave. It requires \opt{behavior()}.
\item Both are optional and independent: use either or both.
\end{itemize}
\begin{lstlisting}
nwwebuse glasgow, nwclear
* the first five actors did not report their ties at wave 2
matrix m1 = J(50,50,0)
matrix m2 = J(50,50,0)
forvalues i = 1/5 {
    forvalues j = 1/50 {
        if `i' != `j' matrix m2[`i',`j'] = 1
    }
}
nwsaom, wave1(glasgow1) wave2(glasgow2) outdegree reciprocity transtrip ///
    missnet(m1 m2) seed(1)
\end{lstlisting}
(This example was run with the development build; it converged, with an overall convergence ratio of 0.119.) Because the missing indicators are Stata matrices, they are limited by Stata's matrix size: 800$\times$800 in Stata/BE, 11,000$\times$11,000 in Stata/SE.

\paragraph{How missing values are handled.} \nwsaom{} follows RSiena's two steps.
\begin{enumerate}
\item \textbf{Imputation.} Each missing dyad is filled in by carrying forward the last observed value (0 if never observed up to that wave). A missing behavior value is filled in from the previous observation, else the next observation, else the mode of that wave (cross-sectional). The imputed values take part in the simulation completely normally; unlike \opt{present()}, missingness does not restrict who can act.
\item \textbf{Masking.} A dyad or actor missing at \emph{either} end wave of a period is excluded from the observed target statistic \emph{and} from every simulated statistic of that period, so the moment condition is not biased by the exclusion. The same applies to the distance that conditional estimation simulates to, and to the distance statistic of the rate under unconditional estimation. The existing effects needed no special-casing: their statistic functions are reused unchanged.
\end{enumerate}
Missing data are handled in the native engine, when the model is otherwise native-eligible; the masked statistic matches the Mata engine to machine precision.

\paragraph{A disclosed approximation.} The statistic of \opt{avalt} and \opt{avsim} for an actor depends on the \emph{current} values of the actor's alters, which differ across simulated replicates. For these effects the masking is only an approximation (it is exact for \opt{linear} and \opt{quadratic}). It is empirically better than not masking, but may be less precise than an idealised per-effect masking under heavy missingness combined with \opt{avalt} or \opt{avsim}.

\paragraph{Missing covariate values.} Covariates of \opt{nodematch()}, \opt{nodecov()}, \opt{nodeicov()}, \opt{nodeocov()}, \opt{simcov()} and their aliases follow RSiena (checked against its source). A missing value is imputed with the covariate mean when actors decide their ministeps, but the \emph{statistic} (target and every simulated statistic) skips a tie whose relevant actor is missing: the alter for \opt{altx()}, the ego for \opt{egox()}, either for \opt{samex()} and \opt{simx()}. With the default centring a missing \opt{altx()}, \opt{egox()} or \opt{nodecov()} value becomes 0 and skipping changes nothing; under \opt{nocenter} and for \opt{samex()}/\opt{simx()} it does, and the range and similarity mean of \opt{simx()} use the observed values only. On RSiena's \texttt{s501}/\texttt{s502} with 8 of 50 covariate values missing, density, reciprocity, altX, egoX and simX agree with RSiena 1.6.6 within sampling noise (simX $0.79$ against $0.78$). An \opt{interact()} naming a \opt{samex()} or \opt{simx()} effect whose variable has missing values is rejected.

\section{Structural zeros and ones: \opt{structural()}}\label{sec:structural}
A structural dyad is one whose tie value is known and cannot change, for example a legally mandated reporting tie, a physically impossible tie, or a dyad that you wish to hold fixed for a counterfactual. It is a simpler idea than missing data: the value is not unknown. RSiena marks such dyads by embedding the sentinel values 10 (structural zero) and 11 (structural one) in the network array. \nwsaom{} uses a \emph{separate} 0/1 mask matrix instead, in the manner of \opt{missnet()}.
\begin{itemize}
\item \opt{structural(matname)} takes \emph{one} 0/1 $n\times n$ matrix with a zero diagonal; a 1 freezes that dyad for the whole period.
\item The observed value of a marked dyad must be \emph{identical} at both waves. A dyad that genuinely changed cannot be structural, and \nwsaom{} rejects it with an error (rc 198) rather than ignore it.
\item Mechanically the dyad is excluded from every actor's candidate set in each ministep, so it can never toggle; the effect statistics and their changes are reused unchanged.
\end{itemize}
The following example marks dyads that are zero in both waves among the first five actors:
\begin{lstlisting}
nwtomata glasgow1, mat(A1)
nwtomata glasgow2, mat(A2)
mata:
S = J(50,50,0)
S[|1,1\5,50|] = (A1[|1,1\5,50|]:==0):*(A2[|1,1\5,50|]:==0)
S = S - diag(diagonal(S))
st_matrix("S", S)
end
nwsaom, wave1(glasgow1) wave2(glasgow2) outdegree reciprocity transtrip ///
    structural(S) seed(1)
\end{lstlisting}
(Also run with the development build; the fit converged with an overall ratio of 0.110.) The structural mask also underlies the two-mode implementation, where only actor--event dyads are free.

\paragraph{Scope.} According to the help file, \opt{structural()} is implemented for the two-wave path \opt{wave1()}/\opt{wave2()}, for network-only models, and it is not combinable with \opt{symmetric}, \opt{ratecov()} or the network endowment/creation split; each of these combinations is rejected outright. The developer's log records that the option also works with \opt{waves()}, which two-mode networks need; the help file's two-wave statement may therefore be out of date. It runs in the native plugin.

\section{What RSiena has that \nwsaom{} does not (yet)}\label{sec:notimpl}
RSiena's effects table, as returned by \texttt{getEffects()} for 12 data configurations of RSiena 1.6.6, has \nTotal{} rows (a row is one RSiena short name for one variable type and interaction context). The developer compared every row with \nwsaom{} by reading the code and the documentation, and by running models against \texttt{siena07} where they were implemented. Of these rows:
\begin{itemize}
\item \nImpl{} are implemented, \nPartial{} is partly implemented;
\item \nNotImpl{} are \emph{not implemented};
\item \nNotPlanned{} are deliberately out of scope: continuous (SDE) behavior and the effects that involve a continuous dependent variable.
\end{itemize}
Of the \nPlannable{} rows that are not out of scope, \pctImpl\% are implemented. The percentage is by \emph{rows}, not by how often an effect is used: the effects most often used in applied papers are largely covered, and the missing rows are concentrated in a few groups. The groups follow; the row-level list is at the end of the chapter.

\subsection{Effects not implemented, by reason}
\begin{description}[leftmargin=0pt,labelindent=0pt]
\item[The generalised method of moments (31 rows).] RSiena's GMoM estimator uses its own statistics (the effects named like \texttt{egoX\_gmm}, \texttt{avAlt\_gmm}, \texttt{crprod\_gmm}, and related placeholders). \nwsaom{} implements the standard method of moments only, so these are not applicable.
\item[The settings model (12 rows).] The \texttt{setting*} effects (\texttt{settingSizeAct}, \texttt{settingOppAct} and relatives) belong to RSiena's settings model, a different simulation procedure in which actors choose within settings. \nwsaom{} has the standard tie-change model only.
\item[Behavior inside multi-network models (37 rows).] Cross-network effects that also involve a behavior variable, such as \texttt{sameWWClosure}, \texttt{covNetNet}, \texttt{inActIntnX}. They need a behavior \emph{inside} \texttt{nwsaom multinet}, which is not available: neither the help file nor the code of \texttt{nwsaom multinet} mentions a behavior variable; behavior co-evolution (\opt{behavior()}) belongs to the single-network command.
\item[Two-mode members in multi-network models (25 rows).] \texttt{nwsaom multinet} supports directed and non-directed members only. Cross-network effects with a two-mode network are not offered.
\item[Rate effects for behaviors and two-mode networks, exposure and infection effects (36 rows).] \nwsaom{} has an estimated constant rate, \opt{ratecov()} with constant node covariates, and the structural rate effects of one-mode networks (\opt{outrate}, \opt{inrate}, \opt{reciprate} and their inverse and logarithmic versions). Rate covariates for two-mode networks and for behaviors, the structural rate effects of behaviors, \texttt{RateX} with a changing covariate, and the exposure and infection effects (\texttt{susceptAvCovar}, \texttt{infectCovar}) are not implemented.
\item[Behavior effects of two networks (8 rows).] For example \texttt{FFDeg}, \texttt{BBDeg}, \texttt{indegMixedPop}: behavior effects that need two other networks.
\item[Effects where \nwsaom{} and \texttt{siena07} disagree, or that are not validated (8 + part of 32 rows).] Rows for a non-directed network with another network (\texttt{outOutActIntn}, \texttt{outOutAvIntn}, \texttt{both}, \ldots), \texttt{degAbsDiffX}, \texttt{degPosDiffX} with the dependent behavior in a non-directed network, and similar cases are described in Chapter~\ref{ch:validation}. The same chapter lists effects where \texttt{siena07} itself crashes (for example \texttt{sameXOutAct} and \texttt{diffXOutAct} in a two-mode network, \texttt{inPop\_ego} for bipartite data), so there is nothing to validate against; \nwsaom{} does not offer them.
\item[Other (32 rows).] Individual effects, among them \texttt{unspInt} in two-mode or non-directed networks (\opt{interact()} is refused there), \texttt{constant} for behaviors (it is collinear with the behavior rate), \texttt{behUnspInt} (no interactions of behavior effects), \texttt{minXAlt} and \texttt{maxXAlt} in non-directed networks, and \texttt{from.w.ind}.
\item[Continuous behavior (80 rows).] Continuous (stochastic differential equation) dependent variables and all effects that involve them are out of scope.
\end{description}
\noindent The grouping is that of the generated list; a row appears under the reason recorded when the inventory was last updated. Where a row's note speaks of \texttt{nwsaom multiplex} or of options that take only fixed Stata variables, the wording may predate later additions (for example \texttt{nwsaom multinet}, \opt{netbeh()}); the heading under which the row is listed, and the counts, are the authoritative statement.

\subsection{RSiena features beyond effects}\label{sec:est-notimpl}
Besides effects, RSiena provides estimation and analysis tools. This is how they compare, as far as the help files and the developer's log show.
\begin{description}[leftmargin=0pt,labelindent=0pt]
\item[Method of moments (\texttt{siena07}).] Implemented, conditional and unconditional, with the same phase structure (Chapter~\ref{ch:estimation}).
\item[Maximum likelihood and Bayesian estimation (\texttt{sienaBayes}).] Not implemented and not planned for now. The developer's reasoning is that they need the full chain of ministeps (insert, delete and permute moves, ministep probabilities) in the plugin and in Mata, weeks of work, and are slow and tuning-sensitive in RSiena, while the open method-of-moments items reach more users. If a likelihood method is added later, maximum likelihood would come first.
\item[Multi-group analysis (\texttt{siena08}).] The meta-analysis of separate fits is available as \texttt{nwsaom\_meta} (random-effects pooling by robust IWLS, heterogeneity tests, Fisher combination, maximum-likelihood mean and between-group sd with profile intervals). RSiena's joint multi-group \emph{estimation} (\texttt{sienaGroupCreate}, one model fitted to several groups at once) is not offered: fit each group separately and pool.
\item[Goodness of fit (\texttt{sienaGOF}).] Available as \texttt{estat gof} (Chapter~\ref{ch:estimation}), with the differences listed there, and not for fits with several co-evolving behaviors.
\item[Composition change.] Available, including fractional join/leave times (\opt{joinat()}/\opt{leaveat()}) as in \texttt{sienaCompositionChange()}.
\item[Continuous behavior.] Not implemented (out of scope).
\item[Simulation only, time-heterogeneity tests, score-type tests, effect importance.] RSiena offers a mode for simulation without estimation, \texttt{sienaTimeTest}, score-type tests, and measures of the relative importance of effects. The \nwsaom{} help files document no counterpart; none of the stored results or options of the three help files covers them. (Two consequences: simulating from a chosen parameter vector is done only inside \texttt{estat gof} and \texttt{estat mems}; and the Wald-type tests of Stata, for example \texttt{test} and \texttt{lincom}, work on the posted \texttt{e(b)} and \texttt{e(V)}, which was checked for a simple \texttt{test} of two coefficients.)
\item[Fixing and testing individual parameters.] RSiena lets you fix an effect's parameter at a value and test it (\texttt{fix}, \texttt{test} arguments of \texttt{includeEffects()}). In \nwsaom{} the starting values are set with \opt{theta0()}, but there is no documented option to hold a chosen effect fixed during estimation (a parameter is held fixed only automatically when its derivative is non-positive, Chapter~\ref{ch:estimation}).
\item[Model types for non-directed relations.] Offered by name or RSiena's modelType number (\opt{symtype()}: forcing, confirmation, force, agree, joint; modelType 2, 3, 4, 5, 6).
\end{description}
I did not verify the statements about \texttt{sienaTimeTest}, the score-type tests, effect importance, the simulation-only mode, the \texttt{fix}/\texttt{test} arguments and the joint multi-group estimation against an RSiena installation for this chapter: they are statements about RSiena's feature set from its documentation, set against the absence of any such option in the \nwsaom{} help files.
